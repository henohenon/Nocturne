## 技術的決定事項

### TD-1: adr/ の位置づけ
- **決定**: adr/ は「実行中に更新し続ける生きたドキュメント」。wip/ は検討段階、adr/ は実行記録、archive/ は完了済み。
- **理由**: これまで wip → 即 archive というサイクルになっており、adr/ が空のまま放置されていた。実行中の記録・問題・判断の変化を残す場所が必要。

### TD-2: archive 化はユーザー承認不要
- **決定**: post-task で adr/ → archive/ は自動実行。必要なら revert すれば良い。
- **理由**: 「archive して良いか確認する」ステップがオーバーヘッドになっていた。記録が正確であれば自動化して問題ない。

### TD-3: デザインファースト閾値の変更
- **以前**: 「2ファイル以上の変更」
- **変更後**: 「設計判断が必要なタスク（アプローチが不明確・アーキテクチャへの影響・自明でないトレードオフ）」
- **理由**: ファイル数は設計の必要性と無関係。定性的な判断の方が実態に合う。

### TD-4: pre-task スキルの強制化
- **決定**: CLAUDE.md 冒頭に `> **First**: ... read pre-task/SKILL.md and execute it.` を追記
- **理由**: process.md の「Run /pre-task」だけでは実際に読まれない。CLAUDE.md は常にロードされるため、そこに書くのが確実。
