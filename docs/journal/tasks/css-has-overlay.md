# タスク: 隠す機能を CSS `:has()` 方式で再実装

## 実施したタスク

### 完了
- `overlay.css` を `:not(:has(許可シグナル))` 方式に書き換え（許可リストは CSS ネストで1か所）
- `content.ts` から MutationObserver・バッジ処理呼び出しを削除
- `badge.ts` / `utils.ts` を削除、`config.ts` からバッジ関連定数を削除
- `.claude/rules/coding.md` の表示ルールを新方式に更新
- 実 YouTube にビルド成果物を注入して検証

## 技術的決定事項

### TD-1: 許可対象
- **決定**: ライブ・ミックスリスト/再生リストのみ許可
- **代替案**: 音楽動画も許可
- **理由**: 音楽判定に使えるシグナルが現行 DOM のロックアップに存在しない

### TD-2: 対象要素
- **決定**: `yt-lockup-view-model` / `ytm-shorts-lockup-view-model` / `ytd-reel-video-renderer` / `ytd-rich-item-renderer`
- **理由**: 現行の主要動画要素 + 従来対象の維持。検索の旧要素 `ytd-video-renderer` は従来通り対象外

## ミス・想定外
- ライブ判定を `.ytBadgeShapeLive` だけと調査ノートに書いたが、関連動画のロックアップでは `.ytBadgeShapeThumbnailLive` だった。検証で発見し許可リストに1行追加して修正。調査時にクラス名ではなくテキストで数えていたのが原因
- ブラウザペインが非表示だと `innerWidth=0` になりヒットテストが無効になる。ビューポートを明示してから検証すること

## 検証結果
- 検索: 通常10件 + Shorts 4件ブロック（クリック不可）、ミックスリストはクリック可
- 関連動画（SPA 遷移後）: 通常72件ブロック（遅延読込分含む）、ライブ6件・ミックス3件は表示・クリック可
- 無効化 → 自動再有効化 → クールダウン: 正常
