# Doc Writing Rules

Write high-level, durable docs. Avoid implementation details.

## Style
- Brief — Use bullets, short sections
- Abstract — Focus on responsibility, not implementation
- Stable — Write what won't change easily
- Decision-focused — Show judgment criteria, not "how to code"

## Checklist
- [ ] Design thinking, not implementation steps?
- [ ] Low-churn content?
- [ ] Judgment criteria shown?
- [ ] Minimal concrete names (entry points, boundaries only)?
- [ ] Concise and readable?
